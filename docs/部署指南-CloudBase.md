## 1. 先搞清楚这是个什么东西

**这不是静态网站，不能用「静态网站托管」。** `web/` 只是前端外壳，真正干活的是 `api/` 里的一个 Python FastAPI 服务。

| 路径 | 作用 |
|---|---|
| `/` | 返回前端页面 `web/index.html` |
| `/static/*` | 托管 `web/style.css`、`web/app.js` |
| `/api/*` | 全部业务接口（`discover` / `explain` / `chat` / `ocr` / `upload` / `notes` / `cards` / `health`） |

**结论：用「云托管」（CloudBase Run，容器），不要用「云函数」。** 三个理由：

- 会话存在**进程内存**里（`sessions/manager.py` 用的是 `dict`）。云函数每次调用都是全新实例，用户点「继续对话」必然 404。
- `/api/discover`（页面上的「发现同源」）单次要跑 **70 秒左右**，云函数默认超时通常不够。
- 有本地文件写入（笔记、卡片、上传附件），云函数的文件系统不可靠。

## 3. 部署：五步，逐字段照填

> 控制台各版本的中文措辞可能略有差别（「代码源」也可能叫「来源」），认字段含义即可。

### 3.1 第一步：新建云托管服务

- 控制台 → **云托管** → 新建服务
- 服务名称：`logic-coloc`
- 环境：选交付方给你的那个环境

### 3.2 第二步：代码来源

| 字段 | 填什么 |
|---|---|
| 来源 | **代码仓库（GitHub 构建）** |
| 仓库 | `https://github.com/Scarlett-yzy/logic-coloc` |
| 分支 | `main` |
| 构建方式 | **Dockerfile** |
| Dockerfile 路径 | 留空（就在仓库根目录） |

> 不用选 Node / Python 之类的「运行时模板」，也不要另外填构建命令 —— 一切都由仓库里的 Dockerfile 决定。
>
> 前提：交付方已经把代码 push 到 `main`。云端拉的是 **GitHub 上的 main**，不是你本地的目录。

### 3.3 第三步：构建与运行配置

| 字段 | 填什么 | 为什么 |
|---|---|---|
| 容器端口 | `8000` | Dockerfile 里 `EXPOSE 8000`；平台注入 `$PORT` 时会自动覆盖，不用管 |
| **请求超时** | **`300` 秒（≥300）** | 「发现同源」单次要跑 70 秒，默认超时太短会在半路被掐断 |
| **最小实例数** | **`1`** | 会话在进程内存里；缩到 0 之后所有会话都丢了，用户点「继续对话」会报 session not found |
| 最大实例数 | `1`（或关闭自动扩容） | 同上：多实例会让人随机拿到 404 |
| CPU / 内存 | 建议 **1 核 2 GB** 起 | 镜像里有 scipy + onnxruntime（图片识图）。构建或运行报内存不足就升到 2 核 4 GB |

**启动命令不用填**，已经写在 Dockerfile 的 `CMD` 里：

```sh
uvicorn logic_coloc.api:app --host 0.0.0.0 --port ${PORT:-8000} \
        --proxy-headers --forwarded-allow-ips='*'
```

**为什么 Dockerfile 里有一行 `COPY . /app/logic_coloc`？** 因为这个仓库目录本身就是一个 Python 包（模块之间用 `from . import …` 相互引用），`/app` 必须是它的父目录，`uvicorn logic_coloc.api:app` 才找得到。**这行不要改**，它替我们规避了最容易踩的目录层级坑。

### 3.4 第四步：环境变量

在服务的「环境变量」里加下面这几条，值照第 4 节的表填：

```
LC_API_KEY=sk-交付方私聊发给你的那串
LC_BRIDGE=https://api.openai-next.com
LC_MODEL=gpt-4o-mini
LC_TIMEOUT=180
LC_DISCOVER_TIMEOUT=240
LC_THINKING=none
LC_SECRET_KEY=自己生成一串足够长的随机字符
```

`LC_SECRET_KEY` 的生成方法（随便哪台机器）：

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

### 3.5 第五步：部署，拿到访问地址

- 点「部署」/「发布」，等构建完成。**首次大约 5~10 分钟**（要下载 scipy、onnxruntime 这些大包），日志里能看到依赖下载
- 构建失败的话，先照第 7 节头两行排查；镜像构建本身每次 push 到 main 都会在 CI 里跑一遍（仓库 → **Actions** → 「容器冒烟」），**先看它是不是绿的** —— 绿了说明云上构建也会成功
- 部署成功后，控制台会给出一个**默认访问地址**（形如 `https://xxxx.service.tcloudbase.com`，自带 https）
- **这个地址就是网站入口**，也是最后要发给大家的东西。先别急着发，走完第 8 节验收再发

## 4. 环境变量说明书（为什么是这些值）

| 变量 | 值 | 说明 |
|---|---|---|
| `LC_API_KEY` | 真实密钥 | 只有这一条需要保密 |
| `LC_BRIDGE` | `https://api.openai-next.com` | **必须一字不差**，见下方硬规定 |
| `LC_MODEL` | `gpt-4o-mini` | 模型名，别改 |
| `LC_TIMEOUT` | `180` | 单次模型调用超时（秒） |
| `LC_DISCOVER_TIMEOUT` | `240` | `discover` 接口的内部上限，必须小于平台的请求超时（300） |
| `LC_THINKING` | `none` | **不要改**，见下方硬规定 |
| `LC_SECRET_KEY` | 随机串 | 身份签名密钥，不配的后果见下 |
| `LC_MAX_GUESTS` | 不填（默认 2000） | 匿名身份上限，演示场景够用 |

可选、有默认值、可以不填：`LC_SAMPLES=3`、`LC_METHOD=cosine`、`LC_THRESHOLD=0.85`、`LC_GAMMA=0.06`。

### ⚠️ 硬规定一：`LC_BRIDGE` 必须一字不差地填 `https://api.openai-next.com`

不要加 `/v1`，不要加结尾斜杠，不要换成别的域名（哪怕那个域名指向同一个服务）。

原因：代码里是靠**域名后缀**判断该说 OpenAI 协议还是 Anthropic 协议的。写法一变，就会**静默**走错协议，表现为「模型返回空内容」，而报错信息**完全不会提示是这个原因** —— 这是最费时间的一个坑。

### ⚠️ 硬规定二：`LC_THINKING` 保持 `none`

踩过的坑：这个兼容端点上传 `disabled` 加低 `max_tokens` 会偶发空响应。保持 `none` 最稳。

### 关于 `LC_SECRET_KEY`（强烈建议配）

不配也能跑：容器第一次用到时会自己生成一份，存到 `data/.secret_key`。但那个文件住在临时容器里，**每次重新部署都会换一把新密钥，于是所有人的身份当场失效**。配了它，密钥由平台固定注入，重新部署不影响已经拿到身份的人（前提是数据本身没丢，见第 5 节）。

镜像里**故意不带** `data/.secret_key`：带着它等于把一个固定密钥烘进镜像，谁拿到镜像谁就能伪造任意人的身份。

### 关于「不用登录」（本站的核心设计，部署时不用额外配）

**打开网站就能用，全程不出现任何账号界面。** 前端首次访问会静默调用 `POST /api/auth/guest`，服务端发一个匿名身份（一个 uid），笔记、卡片、能量照常可用，**各人的数据互不可见**。

设置里只有「账户与资料」和「关于知源」两项 —— **没有登录、没有注册、没有绑定**。网页上唯一可能出现的一层覆盖是**拿不到匿名身份**（断网、后端没起来）时的兜底提示，上面只有一句说明和一个「刷新重试」；正常打开网站它永远不出现。

> 后端其实保留了完整的注册 / 登录 / 绑定接口（`api/auth_store.py`），但**前端没有任何入口**，属于备用能力，不用管它。

对部署有三处影响，都不需要额外配置，但要知道：

1. `data/users.json` 会被陌生访客持续追加（每个新浏览器一条匿名记录）。超过 `LC_MAX_GUESTS`（默认 2000）时，**只从 `users.json` 里摘掉最早的那条记录**，磁盘上的 `data/users/<uid>/` 和 `uploads/<uid>/` 不删（删文件不可逆）。被摘掉的那个 token 校验不过，等价于「很久没来的匿名身份过期了」。
2. 匿名身份也住在 `data/` 里，所以第 5 节的持久化卷同时是「用户数据别丢」的前提。
3. **换一台设备 / 换一个浏览器就是一个新身份**，看不到上一台存的东西 —— 这是本设计的既定取舍，不是 bug。同理，容器**重新部署会让浏览器里存着的旧身份作废**，用户重新打开网站时会拿到一个新身份、看到空书架（数据还在盘上，只是不再属于新身份）。**演示前别重新部署。**

## 5. 让所有人都能正常用：挂持久化卷（强烈建议）

**这是「部署完大家能正常使用」最关键的一步。**

现状：笔记、卡片、复盘记录、头像、上传的附件，以及**身份记录本身**（`data/users.json` + `data/users/<uid>/`），全都存在容器本地文件里。而容器的文件系统是**临时的** —— 重新部署、重启、扩容都会清空。清空之后用户重新打开网站，之前存的东西就都没了。

**做法**（控制台里的措辞可能是「存储」「数据卷」「持久化」或 CFS，含义一样）：

| 挂载到容器的路径 | 存的是什么 |
|---|---|
| `/app/logic_coloc/data` | 身份记录、笔记、卡片、复盘记录 |
| `/app/logic_coloc/uploads` | 上传的附件、头像 |

两个都要挂。挂完**重新部署一次**让配置生效，然后再走第 6 节和第 8 节的验证。

⚠️ **注意这只保住服务端的数据，保不住浏览器里的身份。** 用户的 uid 存在他自己浏览器的 `localStorage` 里；容器一重新部署，`LC_SECRET_KEY` 若没固定就换了密钥，老身份当场作废，用户重新打开会拿到一个新 uid、看到空书架。盘上的老数据还在（可以人工翻 `data/users/<uid>/` 抢救），但**对用户来说就是没了**。所以：**正式演示前把配置一次调好、别再重新部署。**

**不做会怎样**：网站照样能打开、能用，但每次重新部署等于全部重来一遍。临时演示可以接受 —— 只要提前跟大家说清楚「这里存的东西不会长期保存」。

## 6. 部署后的验证（命令行）

把 `你的域名` 换成 3.5 步拿到的地址，按顺序做，每一步过了再往下。

**1. 健康检查**

```bash
curl https://你的域名/api/health
```

期望看到：

```json
{"code":0,"api":"ok","llm_bridge":{"ok":true,"host":"api.openai-next.com","port":443},"model":"gpt-4o-mini"}
```

`code` 是 `0` 且 `llm_bridge.ok` 是 `true` 才算通。如果返回 `503`，说明容器连不上模型端点 —— 检查出网和 `LC_API_KEY`。

**2. 静态资源**

```bash
curl -o /dev/null -w "%{http_code}\n" https://你的域名/
curl -o /dev/null -w "%{http_code}\n" https://你的域名/static/app.js
```

两个都应该是 `200`。

**3. 匿名身份能建出来（本站没有登录，这一步最容易在后面才发现坏）**

```bash
curl -s -X POST https://你的域名/api/auth/guest
```

期望 `code:0` 加一个 `token`，且 `user.guest` 是 `true`。拿这个 token 去访问一个受保护接口，应该是 `200` 而不是 `401`：

```bash
curl -s -o /dev/null -w "%{http_code}\n" -H "Authorization: Bearer 上面那个token" https://你的域名/api/auth/me
```

**4. 浏览器打开域名** —— 应该**直接进应用，不出现任何账号界面**（设置里点开也只有「账户与资料」「关于知源」两项）。页面上也不该出现「模型服务未连接」。

万一看到一层「正在连接服务… / 无法连接服务器」的提示页，那是**后端没起来或断网**的兜底提示，不是登录页 —— 先回头做第 1 步。

**5. 跑一次真实业务** —— 输入一段文字，点「发现同源」，**第一次要等 70 秒左右**（正常，不是卡死）。

## 7. 排错对照表

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 构建失败，日志停在 apt / pip 那几行 | 网络或系统库问题 | 先看日志最后 40 行；再去仓库 → Actions → 「容器冒烟」看最近一次是不是绿的（那次跑的就是同一套 Dockerfile） |
| 构建或运行报内存不足（OOM） | 实例规格太小 | CPU / 内存升到 2 核 4 GB 再试 |
| 服务起不来，日志报 `ModuleNotFoundError: logic_coloc` | 包层级错了，多半是动了 Dockerfile 的 `COPY` | 用仓库自带的 Dockerfile，不要改那一行 |
| 页面一片空白 / 资源 404 | 前端没和后端同源 | 用容器自带的域名访问（同源），不要自己再拼一个静态托管 |
| 提示「模型服务未连接」 | ① `LC_API_KEY` 没配或配错 ② 容器出网被限 | 先 `curl /api/health` 看 `detail` 字段 |
| 「发现同源」转很久然后报「模型服务异常」 | 平台请求超时小于 240 秒 | 把请求超时调到 **≥300 秒** |
| 「发现同源」返回空内容 / 报错信息很奇怪 | **`LC_BRIDGE` 写得不一样** | 改回 `https://api.openai-next.com`，一字不差 |
| `/api/chat` 报 session not found | 用了云函数，或者多实例部署 | 换云托管，并把实例数固定为 1 |
| **打开网站看到一层「无法连接服务器 / 刷新重试」** | 匿名身份没建出来（断网或后端没起来），前端才盖这一层 | 先 `curl -X POST /api/auth/guest` 看有没有 `token`；没有就是后端的问题，**不是前端坏了** |
| 点「刷新重试」后还是那一层 | 后端仍然连不上 | 回头做第 6 节第 1 步；`/api/health` 通了这一层自然会消失 |
| 接口全返回 401 | 前端请求没带 token | 前端新加接口要走 `authFetch`，别直接调 `fetch` |
| `/api/ocr` 报 500 | 镜像里缺 `rapidocr_onnxruntime` | 确认 `requirements.txt` 里那行没被删 |
| 上传的附件重启后打不开 | 容器文件系统是临时的 | 挂持久化卷（第 5 节） |
| 用户的数据在重新部署后没了 | 没挂持久化卷 | 见第 5 节 |
| 用户说「我的东西全不见了」 | 多半是浏览器里那个旧身份作废了（重新部署 / 没固定 `LC_SECRET_KEY`），前端当场给他换了一个新 uid | 配上 `LC_SECRET_KEY`、挂好持久化卷，然后**别再重新部署**；老数据还在 `data/users/<uid>/` 里，可人工抢救 |
| 一个人换台设备就看不到自己的东西 | 本站没有登录，身份只存在他自己浏览器里 | **设计如此**，不是故障；演示时固定用同一台设备同一个浏览器 |

## 9. 已知限制（提前知道，别当成 bug）

1. **不挂持久化卷的话，重新部署会清空全部数据**，见第 5 节。
2. **没有登录，也不打算有**：身份由前端自动领取，只存在用户自己的浏览器里。因此**换设备 / 换浏览器 / 清浏览器数据 = 换一个人**，看不到之前的笔记；容器重新部署也会让老身份作废。这是为了「点击即用」刻意做的取舍。
3. **没有离线兜底**：核心功能每次都要实时调模型，模型端点不通就等于网站不可用。演示前务必确认额度和出网。
4. **「发现同源」单次 70 秒**是设计如此（要跑多次采样再生成学习报告），不是性能问题。
5. **实例数必须固定为 1**：会话在内存里，多实例会让 `/api/chat` 随机 404。
6. 模型端点暂时不可用时，`/api/discover` 会返回 `code:500` 加「模型服务异常，请稍后重试」，**不会崩**。

## 10. 以后改了代码，怎么更新线上

1. 交付方把改动 push 到 `main`
2. 控制台 → 该服务 → **重新部署**（也可以开启「自动构建 / 持续部署」，push 后自动重建）
3. 前端（`web/` 里的 `app.js`、`style.css`、`index.html`）改完，等构建完用户刷新页面就拿到新版
4. 后端（`api/`、`agents/`、`rag/`、`sessions/`）改完**必须重新部署**才生效
5. `data/corpus/example.jsonl`（语料库）改完也必须重新部署 —— 服务启动时一次性加载

## 11. 附录

### 11.1 交付方本地先跑一遍（Windows）

```bash
cd /e
python -m uvicorn logic_coloc.api:app --host 127.0.0.1 --port 8000 --proxy-headers --forwarded-allow-ips='*'
```

浏览器开 `http://127.0.0.1:8000/`。必须从 `E:\` 下启动（不是 `E:\logic_coloc` 里），因为包的父目录要在 `sys.path` 上。

### 11.2 前后端同源（推荐，也是默认）

前端和后端放在同一个域名下（就用容器自带的地址）：静态资源（`/static/*`）和接口（`/api/*`）天然打通，**不用改 CORS、也不用改前端代码**（`web/app.js` 里 `API_BASE = window.LC_API_BASE || ""` 默认就是同源）。

### 11.3 一定要前后端分离部署的话

1. 在 `index.html` 引 `app.js` 之前插入 `<script>window.LC_API_BASE = "https://后端域名";</script>`
2. 改 `api/__init__.py` 里的 CORS 白名单（现在只有 `localhost:5500` 和 `8080`），把前端域名加进去
3. `/uploads/*` 必须能公网直接访问（`<img>` 不会带 `Authorization` 头），它靠「随机 uid + 随机文件名」保护
4. 前端所有请求都走 `authFetch`，新加接口别直接调 `fetch`
